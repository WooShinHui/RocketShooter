# +1 게임 공통 템플릿 — 중간본 v0.1

기준 프로젝트: RocketShooter. 기준일: 2026-10-06. **로켓을 타는 동작만 교체하고, 성장·경제·UI·주변 시스템은 그대로 재사용한다.** 이 폴더는 Gemini, Claude, Codex가 함께 읽는 구현 기준이다. 완성된 범용 엔진이라는 뜻은 아니며, 현재 구현을 동결한 소스와 범용화 연결 규약을 함께 제공하는 중간 템플릿이다.

사용자가 **“야 혓바닥으로 +1게임 만들자. 기존 템플릿 사용해”**라고 하면 먼저 이 문서와 아래 문서를 읽는다. 돌 던지기, 침 뱉기, 혓바닥, 칼 휘두르기를 이유로 레벨 곡선, 환생 초기화, 장비 소유권, 자동 클릭, 메뉴 위치를 새로 설계하지 않는다. 제목·행동 연출·행동 입력·서버 판정·행동 전용 환경만 바꾸고, 나머지는 아래 계약과 동결 소스대로 이식한다. UI의 아이콘/문구 변경도 사용자의 별도 요청이 없으면 그대로 둔다.

## 읽는 순서

1. [UI_LAYOUT.md](UI_LAYOUT.md): 화면 배치, 스타일, 반응형, 팝업, 표시 상태.
2. [LIFECYCLE.md](LIFECYCLE.md): 접속 → 성장 → 행동 → 보상 → 복귀 → 환생 → 저장.
3. [ECONOMY.md](ECONOMY.md): 숫자·공식·영구 구매·세션 부스트.
4. [EVENTS_AND_DATA.md](EVENTS_AND_DATA.md): 버튼별 이벤트, 원격 통신, 속성, 데이터.
5. [ACTION_ADAPTER.md](ACTION_ADAPTER.md): 공통 코어와 행동 모듈의 교체 경계.
6. [REUSE_AND_ACCEPTANCE.md](REUSE_AND_ACCEPTANCE.md): 새 게임 적용 순서와 동일성 검사.
7. [STATUS.md](STATUS.md): 현재 구현/미구현/테스트 기능과 검증 한계.

## 우선순위와 변경 규칙

사용자의 최신 지시 → 이 v0.1의 규격 문서 → 동결 소스 → 실제 캡처 → 동결 소스 안의 과거 개발 기록 순서다. 과거 기록에 있던 Gifts 도크, 정사각형 그리드, 금화 업그레이드, 유료 상품 계획을 현재 기능으로 복원하지 않는다. 문서와 동결 소스가 충돌하면 임의로 선택하지 말고 정확한 차이와 파일 위치를 보고한다.

`v0.1`은 읽기용 기준이다. 새 게임은 자기 저장소에서 이식하고, 이 프로젝트나 다른 게임을 수정하지 않는다. 현재 RocketShooter를 계속 개발해 규격이 바뀌면 새 `v0.2`를 만들고 변경 기록을 남긴다. 다른 AI가 참고할 수 있도록 루트 `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`도 이 폴더로 안내한다.

## 복제 범위

고정되는 것: 클릭/자동 클릭/기본 온라인 XP, 레벨 곡선, 환생, 트로피 잔액, 장비/트레일 영구 소유, 훈련소, 부스트/음식/친구 효과, UI 위치·팝업·애니메이션·입력 차단, 결과/복귀의 공통 상태, 데이터 준비·저장·검증, 공통 보너스 이벤트의 주기와 지급 규칙.

교체되는 것: 로켓 모델·탑승·상승·다이브 물리, 발사대 트리거, 카메라의 행동 연출, 고도 기반 목표 배치·접촉 판정, 행동 전용 VFX/SFX와 측정 단위. 공통 경제에는 검증된 행동 결과만 전달한다. 고도 표시나 Fast Dive 같은 행동 전용 UI는 대응 행동의 상태/메트릭을 표시하는 어댑터로 바꾸되 공통 메뉴·하단 게이지의 배치를 바꾸지 않는다.
