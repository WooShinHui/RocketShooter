# 행동 교체 계약: 로켓 / 돌 / 침 / 혓바닥 / 검

**이 문서는 다음 게임 구현 계약이며 현재 RocketShooter가 이미 분리된 범용 엔진이라는 뜻은 아니다.** `contracts/ActionContract.luau`는 타입/규약 예제다. 기존 동결 소스는 검증할 실제 구현을 제공한다. 다음 게임에서 이 계약을 구현하고 기존 결합부만 브리지한다.

## 소유권 경계

| 공통 코어: 바꾸지 않음 | 행동 어댑터: 교체 가능 |
|---|---|
| 프로필/레벨/환생/영구소유/통화/저장 | 모델·발사체·탑승·애니메이션 |
| 수동XP/자동XP/온라인XP/훈련XP | 행동시작트리거/조준/방향/행동쿨다운입력 |
| 부스트·음식·친구·XP/보상배율 | Power→물리/거리/범위변환 |
| UI 전체레이아웃/테마/모달/입력잠금 | 행동전용카메라·메트릭문구·보조제어 |
| 공통RunId/현재캐릭터/단일정산/복귀상태 | 적중기하/목표생성/서버검증된성공조건 |
| 논리목표중복방지/트로피단계/결과잔액커밋 | 로켓고도→새행동진행구간매핑 |
| 공유보너스주기/최대청구/XP지급 | 링교차→돌표적/침표적/검보너스표적판정 |
| 쇼룸영구구매/훈련소진입·퇴장 | 장비가캐릭터/행동대상에붙는연출 |

`PlayerData`/`ClickerService`/`TrainingService`/`SharedTraining`/`PowerBoosts`/`TotalHud`/`ClickerUI`/`SimulatorHUD`/`SimulatorTheme`/`MenuOverlay`/`ProgressionConfig`는 공통 또는 공통결합 코드다. `RocketFlightService`에는 현재 공통 Run 정산과 로켓 행동이 섞여 있다. 파일 이름만 보고 모두 삭제하지 않는다.

`RocketMotion`/`RocketPose`/`BackRocket`/`DiveImpact`/`FlightCamera`/`SteeringInput`/`RocketInput`/`StageCurtains`/`CloudGate*`/`BreakCourse`/`DiveBreakZone`/`SkyLife`/`LaunchPadGuide`는 로켓 행동/월드 표현 예제다. 다른 행동에서 그대로 실행할 필요는 없다. 이 코드에 들어 있는 보상·중복방지·RunId 의미는 공통 규약으로 가져온다.

## 통일 상태와 호환 브리지

새 코어의 개념상 상태는 Loading,Idle,Acting,Result,Returning,Closed. v0.1 UI/서버는 `FlightState`와`Flying`을 직접 참조하므로 초기 이식 때 **Acting을FlightState=Flying으로 게시하는 호환 브리지**가 필요하다. 조용히State만이름을바꾸면훈련·부스트·메뉴·수동클릭표시가깨진다. 모든사용처는API_INVENTORY로점검한다.

로드는DataReady로따로표현된다. Cancellation알림후경제상태Idle복구;Dive는로켓어댑터내부모드. 서버소유RunId와Character를모든상태/적중/결과알림에붙인다. 다음게임의새입력Remote는버튼/방향/조준만받고클라이언트보상량을받지않는다. 현재Remotes와어댑터매핑을함께남긴다.

## 서버 계약

1. `CanStart(context,input)`은프로필준비/Idle/살아있는현재캐릭터/쿨다운/서버유효입력/자기시작트리거를검사한다. 경제값은변경하지않는다.
2. 코어는 RunId·Character·원시Power·장비보너스·시작시간을동결한다. 온라인/클릭XP의라이브Level이이번행동을재가속하지않는다.
3. `Start`는어댑터객체를생성한다. 서버만현재Run을소유한다. 클라이언트의애니메이션종료가공식완료신호가아니다.
4. `Step(dt)`/`HandleInput`은물리·애니메이션·서버기하를진행한다. 코어의검증된Hit 경로만 호출한다. TargetId는파편ID가아닌논리목표ID.
5. 코어는중복아닌적중에보상단계/Wins유효배율을1회적용해미정산잔액에더한다. 서버계산한시작/시간XP는기존소수/배율/팝업경로를사용한다.
6. 성공완료시코어가잔액/기록을1회커밋하고결과UI를게시한다. 실패완료시미정산트로피를버리고이미지급한XP는유지한다.
7. `Cleanup`은여러번호출해도안전하게자기연결·타깃·발사체·시각물을해제한다. 코어는훈련/이동잠금/상태를복구하고Idle로돌린다. 다른플레이어의대상/세션은건드리지않는다.

보상콜백은신뢰된서버모듈안에서만노출한다. public클라이언트Remote가`Award(count,multiplier)`를부를수없다. 결과패킷은숫자표시용이며저장의원본은서버프로필이다. Data.AwardFlightXP의Flying검사를없애버리는대신호환브리지또는명시적중립API에서검증한다.

## 행동별 연결 예

| 행동 | Start/Step | 서버Hit | 완료/측정값 | 유지되는 것 |
|---|---|---|---|---|
| Rocket | 발사대접근/탑승상승/강하 | swept기하/구름/파괴목표 | 착지·고도/시간/적중 | 전체공통코어 |
| Stone | 투척준비/서버발사체 | 서버궤적과표적교차 | 정지·거리/적중 | 같은XP·트로피·환생·UI |
| Spit/Tongue | 공격발사/혀연장 | 서버궤적/범위·동일Target중복차단 | 회수/최대도달거리·적중 | 같은장비·훈련·부스트·UI |
| Sword | 스윙/서버스윙시간창 | 서버범위/각도/대상·한스윙한Target | 스윙완료·거리/단계·적중 | 같은경제·저장·모달 |

돌/침/검도 “한행동Run”의시작/미정산보상/성공정산/실패정리규칙을사용한다. 연속공격게임에서는스윙1회가Run인지여러스윙묶음이Run인지행동정의에명시한다. 변경된Run길이가성장/트로피속도를과도하게바꾸면단계/시간슬롯매핑을제시하고사용자지시없이다른경제로확정하지않는다.

## 정확한 이식 방법

현코드를단순히Enabled=false로돌리면옛금화경제/대포분기가실행되므로금지한다. 안전한첫이식은공통Config/데이터/UI/서비스를복사하고모든행동상태검사에호환브리지를유지한뒤새서버ActionService가로켓서비스의Run정산부분을대체하는것이다. 바꾸는파일/함수마다기존함수→새함수매핑을기록한다. 로켓전용엔트리포인트를이중실행하지않고옛FlightService의보상을동시에지급하지않는다.

장비명/아이콘/행동Power변환/행동측정단위이외의디자인변경은별도요청이필요하다. 현재UI를똑같이보존하려면Rocket아이콘이남는것도기본값이다. 사용자가행동테마아이콘변경을요청한경우해당자리의이미지만바꾸고배치·애니메이션·버튼이벤트는그대로둔다.
